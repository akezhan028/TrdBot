# Threads Bot

#### Video Demo: <ВСТАВЬТЕ_ССЫЛКУ_НА_ВИДЕО>

#### Description

Threads Bot — это мой финальный проект для курса **CS50's Introduction to
Programming with Python**. Это настольное приложение на Python, которое
автоматизирует осмысленное взаимодействие в социальной сети
[Threads](https://www.threads.net): находит свежие посты по интересующим
темам, отбирает подходящие из них с помощью ключевых слов и искусственного
интеллекта (OpenAI), генерирует релевантный комментарий в нужном тоне и
публикует его — при этом ставит лайк. Всё это управляется через понятный
графический интерфейс (GUI) на `tkinter`.

Идея проекта в том, чтобы вместо ручного и однообразного «сидения в ленте»
человек мог задать темы, стиль общения и лимиты, а программа делала бы
рутинную часть: читала посты, отсеивала спам и нерелевантное, писала
естественные, «человеческие» комментарии и вела статистику. Проект
объединяет несколько тем курса: работа со строками, функции, файлы (JSON и
INI), регулярность и структурирование кода, обработка исключений,
модульность и, конечно, тестирование с помощью `pytest`.

## Как это работает

Пользователь запускает приложение и в графическом интерфейсе указывает:

* **API-ключ OpenAI** и промпт, задающий стиль комментариев;
* **ключевые слова / темы**, по которым бот ищет посты;
* **лимиты** (сколько комментариев оставить, задержки между действиями,
  скорость печати) — чтобы поведение выглядело естественно;
* включать ли **ИИ-анализ** каждого поста перед комментированием.

После запуска бот открывает браузер через **Playwright**, ждёт авторизации
пользователя в Threads, а затем в цикле: прокручивает ленту, собирает посты,
отсеивает уже обработанные и не подходящие по темам, спрашивает у модели
OpenAI, стоит ли комментировать этот пост и в каком тоне, генерирует
комментарий и публикует его. Все обработанные посты запоминаются в файле,
чтобы не комментировать одно и то же дважды.

## Файлы проекта

### `project.py`

Основной файл. В его начале находятся **функции верхнего уровня с чистой
логикой** — именно они покрыты тестами, потому что не зависят от сети, GUI
или внешних сервисов:

* **`clean_message(message)`** — заменяет эмодзи в тексте логов на текстовые
  метки (`🚀` → `[START]`, `✅` → `[OK]` и т.д.). Это нужно, потому что
  консоль Windows часто не умеет печатать эмодзи и падает с ошибкой.
* **`parse_keywords(keywords_str)`** — превращает введённую пользователем
  строку вида `"Python, AI, крипта"` в аккуратный список ключевых слов в
  нижнем регистре, отбрасывая пустые элементы и лишние пробелы.
* **`matches_topic_filter(post_text, keywords, min_matches=1)`** — проверяет,
  подходит ли текст поста под заданные темы: содержит ли он хотя бы
  `min_matches` ключевых слов (без учёта регистра). Пустой список ключевых
  слов трактуется как «фильтр выключен».
* **`make_post_id(author, text)`** — строит стабильный `SHA-256`
  идентификатор поста по имени автора и тексту, чтобы бот не комментировал
  один и тот же пост повторно между запусками.
* **`is_valid_api_key(api_key)`** — простая проверка, что введённый ключ
  похож на настоящий ключ OpenAI (начинается с `sk-`), до попытки запроса.
* **`select_tone_instruction(tone)`** — по названию тона
  (`friendly`, `professional`, `enthusiastic`, `supportive`, `neutral`)
  возвращает текстовую инструкцию для модели; для неизвестного тона
  используется нейтральный вариант.

Ниже расположены два класса, которые используют эти функции:

* **`ThreadsBotCore`** — «мотор» бота: настройка браузера, авторизация,
  поиск и фильтрация постов, обращения к OpenAI для анализа и генерации
  комментариев, публикация, ведение статистики и сохранение состояния.
* **`ThreadsBotGUI`** — графический интерфейс на `tkinter`: вкладки с
  настройками и логами, кнопки запуска/остановки, прогресс-бар, сохранение
  и загрузка конфигурации в `.ini`-файл, запуск бота в отдельном потоке,
  чтобы интерфейс не «зависал».

Функция **`main()`** — точка входа: она запускает графический интерфейс
(и аккуратно сообщает пользователю, если в системе не установлен `tkinter`).
Как принято в CS50, `main()` вызывается в конце файла через
`if __name__ == "__main__": main()`.

### `test_project.py`

Тесты на `pytest` для всех перечисленных выше функций верхнего уровня. Для
каждой функции проверяются как обычные случаи, так и граничные (пустая
строка, отсутствие совпадений, неизвестный тон, невалидный ключ). Тесты
намеренно покрывают именно чистую логику, которую можно проверить без
браузера и без обращений к OpenAI.

### `requirements.txt`

Список внешних библиотек: `openai` (доступ к модели), `playwright`
(управление браузером), `pandas` и `openpyxl` (работа с данными), а также
`pytest` для тестов.

## Дизайн-решения

Изначально вся логика была спрятана внутри методов классов. Чтобы код было
удобно тестировать (и чтобы соответствовать требованиям CS50 — `main()` и
как минимум три собственные функции на верхнем уровне), я **вынес чистую,
не зависящую от внешнего мира логику в отдельные функции модуля**, а методы
классов теперь просто вызывают их. Это убрало дублирование и сделало
поведение проверяемым в тестах.

Ещё одно осознанное решение — **мягкий импорт** «тяжёлых» и системных
зависимостей (`tkinter`, `playwright`, `openai`, `pandas`). Модуль можно
импортировать и протестировать даже в окружении, где не установлен GUI или
нет доступа к сети: соответствующие флаги (`GUI_AVAILABLE`,
`DEPENDENCIES_OK`) просто выставляются в `False`, а `main()` понятно
объясняет пользователю, чего не хватает. Благодаря этому тесты не требуют
графической среды и запускаются где угодно.

## Установка и запуск

```bash
pip install -r requirements.txt
playwright install chromium
python project.py
```

Запуск тестов:

```bash
pytest test_project.py
```
